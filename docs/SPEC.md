## 1. Права
- Все коды прав — `backend/app/permissions.py` (100 флажков + 5 прав-выборов). Это 1-в-1 LiveSklad.
- Владелец (`Employee.is_owner`) может всё.
- Права-выборы (`Role.scopes`): orders = none|all|own («own» — только заказы, где сотрудник мастер,
  менеджер или создатель), tasks, cart, salary (none|all|own|locations), orderSalary (none|own|all).
- Сотрудник видит только свои локации (`employee.locations`), владелец — все.

## 2. Заказ
### 2.1 Жизненный цикл
Статусы в 5 группах (`StatusGroup`): new → inWork → wait → finish → closed. Внутри группы — свои статусы
(см. seed_data.json → statuses). Переход возможен между любыми статусами, если позволяет role_access.
Вся логика смены статуса — `services.orders.change_status` (уже написана):
- `pay_required` — нельзя перевести, пока долг > 0;
- `comment_mode = required` — нужен комментарий;
- первый вход в finish ставит `finished_at`; вход в closed ставит `closed_at`, `closed_by_id` и начисляет долг клиенту;
- выход из closed откатывает начисление.

### 2.2 Создание заказа
1. Выбрать тип заказа → форма строится из `FormField` этого типа (поля, порядок `place`, обязательность, значения по умолчанию).
2. Клиент: поиск по телефону (нормализовать до цифр, 8XXXXXXXXXX → 7XXXXXXXXXX). Нашёлся — подставить, нет — создать.
3. Номер — `services.orders.next_order_number` (продолжает нумерацию LiveSklad с A15843).
4. Статус — первый статус группы new (по sort). Мастер/менеджер по умолчанию — текущий пользователь, если так в форме.
5. Запись в историю `created`.

### 2.3 Позиции, оплаты, история
Только через `services.orders`: add_position / remove_position / update_position_price / pay / refund /
delete_payment / change_status / add_history. Роутер проверяет права и делает commit.
Права на позиции: changeOrderPositionAccess; запчасть без работы — createOrderProductAccess;
цена ниже минимальной — minPriceAccess; видеть себестоимость/прибыль — purchasePriceAccess / marginPriceAccess.

### 2.4 Список заказов
Колонки: Заказ (номер), Статус (цвет), Крайний срок, Менеджер, Дата создания, Тип заказа, Тип устройства,
Устройство (бренд + модель), Неисправность, Контрагент (имя + телефон), Сумма (total_price; оплачено — мелко).
Вкладки-счётчики по группам статусов: Новые / В работе / Отложенные / Готовые / Выданные / Все.
Фильтры: локация, статус, тип заказа, мастер, менеджер, период, «срочные», «просроченные» (deadline < сейчас и не closed).
Поиск: номер, телефон, имя, серийный номер, модель. Пагинация по 50.

## 3. Деньги — `services.money` (уже написан)
- amount > 0, направление от статьи. Нал и безнал раздельно.
- Безнал-приход в кассу с bank_percent > 0 → автоматом расход «Комиссия банка».
- Статьи с affects_balance двигают Counteragent.balance. Выданный заказ — charge_counteragent.
- Перемещение между кассами — `move_money` (две связанные транзакции).
- Удаление — мягкое, с откатом. Закрытый период (`Company.date_lock`) менять нельзя.

## 4. Склад — `services.stock` (уже написан)
Скользящая средняя себестоимость. Минус на складе запрещён. Работы на складе не учитываются.
Документы (StockDocument): поступление, перемещение, списание, возврат от клиента, возврат поставщику,
инвентаризация. Проведение документа = вызовы stock.receive / write_off / move по позициям, is_posted=True.
Отмена проведения (удаление документа) = обратные вызовы.

## 5. Продажи
Чек (Sale) в локации: позиции из остатков склада (write_off) или работы, скидка, оплата через money
(статья SALE). Возврат по чеку — документ SALE_RETURN + транзакция SALE_RETURN.

## 6. Справочники
Контрагенты, номенклатура (+группы, цены по типам цен), типы устройств → бренды → модели,
неисправности, комплектация, рекламные источники, статьи денег, единицы измерения, типы контрагентов.
